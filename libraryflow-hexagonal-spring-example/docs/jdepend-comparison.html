4. Instability (I)

Berechnet als Ce / (Ca + Ce). I = 0 bedeutet maximal stabil (viele Abhängige, schwer änderbar), I = 1 bedeutet maximal instabil (abhängig von anderen, keine eigenen Abhängigen). Ideal ist eine klare Differenzierung: stabile Kern-Packages (niedriges I) und instabile Adapter (I → 1). Der aggregierte Durchschnitt ist wenig aussagekräftig — die Subpackage-Werte zeigen die tatsächliche Architekturqualität.

5. Distance from Main Sequence (D)

Berechnet als |A + I − 1|. Ideal ist D = 0 (auf der Hauptsequenz-Linie). Hohe D-Werte deuten auf Packages in der „Zone of Pain" (stabil + konkret, schwer änderbar) oder der „Zone of Uselessness" (instabil + abstrakt, ohne Nutzen) hin. Je näher an 0, desto besser ausbalanciert.

8. Max Ce (Efferent Coupling) — Hotspot-Analyse

Der höchste Ce-Wert eines einzelnen Packages im Modul. Dieser Wert identifiziert den größten Hotspot: das Package mit den meisten ausgehenden Abhängigkeiten — und damit die höchste Empfindlichkeit gegenüber externen Änderungen. Niedrigere Werte zeigen eine bessere Verteilung der Verantwortlichkeiten.

Subpackage-Zuordnung: Vergleichbare Packages der vier Module werden einander zugeordnet (z.B. Layered „model" ≈ Red „domain.model" ≈ Blue „app.model" ≈ Green „app.shared"). „—" bedeutet: Kein vergleichbares Package in dieser Architekturvariante vorhanden.
Datenquelle: JDepend-Analyse der jeweiligen target/jdepend-report.xml. Nur Packages mit Präfix com.javaland.libraryflow wurden berücksichtigt — externe Abhängigkeiten (Spring, Jakarta, SLF4J etc.) sind ausgeschlossen.
Blue = Hexagonal mit Domain-Driven Ports (ohne explizite Bounded Contexts). Green = Hexagonal mit Bounded-Context-Packages (app.borrowing, app.catalog, app.users, app.administration).
